Guide

Translate, inspect, then export

Tolmach keeps the draft, refinement and quality evidence separate. The final panel is the text you export; the draft remains available to compare whenever refinement needs a second look.

Workflow

Step by step

  1. Upload a file — → 1 UPLOAD

    Click Upload on the Original text panel, or drag a .txt or .epub file onto it. The source preview appears immediately; the full file is what actually gets translated.

  2. Set language pair and genre

    Choose source, target and genre. Genre guides the translation prompt; it is not a claim that the app can identify genre automatically. In Settings, assign separate local Ollama models to Translation, Refinement, Verifier, Prepare and Judge. Keeping the graders separate is not tidiness: a model asked to rule on its own edit or its own translation answers by position rather than by content.

    TranslateGemma (translategemma:4b, 12b or 27b) is supported for Start and receives its native translation prompt with the glossary and nearby context included. It is translation-only: use general instruct models for Prepare, Continue and LLM judge tests. Backtranslation is allowed because it is another translation pass.

  3. Prepare and review the glossary — optional

    Open Glossary and press → PREPARE after uploading the source. This is a document-wide analysis, not translation: GLiNER finds entity candidates, recurring source forms are clustered, the entity-resolution model rules on that clustering — confirming what belongs together and splitting what does not — and the glossary-rendering model then proposes a target rendering and enforcement mode for each name, working from that name's own quoted context. Both roles are chosen in Settings; identity is the one that repays a larger model.

    The result is a proposal, not verified terminology. Review every line, remove noise, correct bad renderings and add anything it missed. If you already wrote a glossary, Prepare deliberately leaves it untouched rather than silently replacing your work. When two distinct source entities receive the same target rendering, the panel warns you to resolve that conflict before Start.

  4. Adjust the glossary by hand — optional

    Use one entry per line: source => target | mode, for example Mr. Darcy => мистер Дарси | exact. Tab-separated rows are accepted too: source[TAB]target[TAB]mode. If omitted, the mode is inflectable.

    exact keeps the target text letter-for-letter and is suited to fixed labels. If a model leaves that exact source spelling in an otherwise translated chunk, Tolmach replaces the literal leak deterministically; it does not guess at a different model-made rendering. inflectable keeps the agreed term but permits grammatical endings, which is normally right for names. preferred is a suggestion the model may depart from when context requires it. Only exact entries are enforced by Terminology delta; all entries contribute to the document-wide consistency check.

  5. Press START — → 2 START

    Runs the first pass: a straight draft translation. Progress and each finished batch stream into the Translation panel as they complete.

  6. Press CONTINUE — → 3 CONTINUE

    Refinement is a guarded patch pass, not a free rewrite. It first identifies quoted draft spans and labels the issue (for example mistranslation, omission, terminology or grammar). Python applies only those located replacements; text outside a valid span is copied unchanged.

    The proposed patch is compared with the draft against the source twice, with the order swapped. It is kept only when the verifier accepts it both times. Set the Verifier role in Settings to a model clearly larger than Refinement: a model ruling on its own edits answers by which version it was shown first, the two orderings then contradict each other, and every patch is rejected — the pass runs and changes nothing. Fixes that can be checked against the source rather than judged — terminology, consistency, omission and addition — are applied without the vote. Style-only and minor subjective suggestions are reported but not applied. A small diff — or no change in a chunk — is normal and preferable to a fluent rewrite that loses meaning.

    The Refinement line in Current job says which of the three happened: how many errors were found and patched, how many chunks changed, how many patches the verifier vetoed, and how many review calls returned nothing at all. Log opens a separate window with the same thing per chunk, live, as the run produces it. Loading a document starts a new log, so the window holds one book at a time; the previous one stays on disk as logs/*.log.1.

  7. Run Quality Check tests — optional

    Each test runs on demand in Current job. Draft tests become available after Start; refinement tests after Continue. Model calls and COMET-Kiwi can be slow, so the app never runs them automatically.

    Deterministic checks read the whole document and catch consistency, missing chunks and factual changes across distant pages. Model-based checks select five high-risk chunks (names, dialogue and numbers). Use a judge model different from the translation model. A result is evidence for investigation, not a substitute for reading an important manuscript.

  8. Export

    Copy, TXT, PDF and EPUB become available after a translation completes. PDF saves a printable HTML file for your browser's Print → Save as PDF flow. EPUB export preserves EPUB input as a translated EPUB; TXT input can be exported as an EPUB too.

  9. Archive

    Every job is saved locally in SQLite. Open restores its panels and saved checks; Continue resumes a draft; Retry re-runs a failed job; Delete permanently removes that job and its chunks.

Quality Check reference

What each test tells you

Translation — needs a draft (after Start)

Backtranslation chrF diagnostic only

ShowsTranslates the draft back into the source language and scores how close that round-trip is to the original, on a 0–100 scale (chrF).
Read itNot a quality score, and no longer part of any composite. chrF measures character overlap with a reference, and a back-translation is not a reference — the number is the combined error of the forward and reverse translations, so it cannot be read as the quality of either. Flagged below 40, which is worth a look, but do not compare the figure across runs.
DoLeft on the default (same model that translated), the reverse leg is really testing self round-trip consistency: a model that translates literally can round-trip itself back almost word-for-word and score high even if the forward translation reads badly, while a model that translates freely and naturally can score lower for a good translation just because it doesn't round-trip cleanly. Fine as a single-run sanity check — but if you're comparing translation models, pick one fixed model here and keep it the same across every model you test. That way the reverse leg is a constant and the only thing changing between runs is the translation model itself, so the chrF difference actually reflects forward-translation quality.

LLM judge choose a judge model

ShowsA separate model rates five sampled chunks 1–5 on adequacy (is the meaning preserved) and fluency (does it read naturally). Chunks are picked by risk — names, dialogue, numbers — not evenly spaced.
Read itFlagged if either average is below 3/5. Pick a judge model different from the one that translated, so it isn't grading its own work. TranslateGemma isn't offered here — asked for a score it would translate the question instead of answering it.
DoLow fluency but high adequacy → fine for a draft, the refinement pass should fix it. Low adequacy → the draft has real translation errors.

COMET-Kiwi gated model

ShowsA reference-free neural quality estimate for the draft (and, after Continue, for the final).
Read itHigher is better; values below 60 are flagged. It is an estimate over chunks, not proof of literary quality or long-range consistency.
SetupInstalled with the app, but Unbabel/wmt22-cometkiwi-da is gated on Hugging Face: request access on the model page, then run huggingface-cli login (or set HF_TOKEN). Its checkpoint downloads on first use. The app reports the problem instead of fabricating a score.
Refinement — needs a refined text (after Continue)

Named-entity consistency no model needed

ShowsFor each glossary term, source chunks where no form of the agreed rendering appears in the final. It reads every aligned chunk; inflected forms count.
Read itMissing terms are flagged. An empty glossary cannot prove consistency, so run Prepare or add terms manually before relying on this check.
LimitStem matching cannot reliably distinguish renderings that differ only by an ending. Inspect those cases manually.

Numbers and dates no model needed

ShowsDigit-written values from the source that are absent or changed in the final.
Read itAny missing source number or date component is flagged. Extra target values are listed for review.
LimitSpelled-out numbers require language-specific parsing and are not covered.

Chunk coverage no model needed

ShowsWhether every source chunk has a non-empty final chunk in the same position.
Read itA count mismatch or blank final chunk is a blocking integrity issue. It catches dropped content but does not judge how well a chunk was translated.

Untranslated words no model needed

ShowsWords in the final text still written in the source's script, listed with counts — Grunnings sitting in the middle of a Cyrillic page.
Read itAny leakage is flagged, because it cannot be judged automatically: a brand kept in Latin on purpose looks identical to a name nobody translated. When source and target share an alphabet (English → German) the test says so and stays quiet — there is no signal there to read.
DoLook at the list. Anything that should have been transcribed goes into the glossary, and then re-run Continue.

Terminology delta no model needed

ShowsViolations of exact glossary constraints in the draft vs. the final text.
Read it"Refinement fixed N violation(s)" is good news. "Introduced N new violation(s)" or any remaining violations are flagged.
DoOnly exact terms are policed here — that is what exact means. Names proposed by Prepare are inflectable on purpose, since pinning a name to one surface form would make the sentence around it ungrammatical; those are covered by Named-entity consistency instead.

Length ratio no model needed

ShowsFinal length ÷ source length, with final ÷ draft reported as a secondary number.
Read itFlagged outside 0.55x–1.6x — truncation or duplication. The band is deliberately wide, because expansion is language-pair specific and this test has no table to compare against.
DoCompare against what your pair normally does: English → Russian usually lands around 1.10–1.20, so a ratio near 1.00 means the translation is compressing even though nothing is flagged. The final ÷ draft number is nearly useless on its own — both texts came out of the same pipeline, so it sits near 1.00 whatever happened to the meaning. That is why it is no longer the headline.

Diff ratio no model needed

ShowsHow similar the draft and final text are (0–1).
Read itBelow 0.75 is flagged — over a quarter of the text moved, which a span-level patch cannot do, so something rewrote it wholesale. High similarity is now the expected outcome, not a complaint: refinement patches reported spans and leaves the rest byte-identical. Above 0.995 means almost nothing was applied — check how many errors the pass reported.
DoA few percent is the healthy range.

Repetition ratio no model needed

ShowsShare of repeated 4-word phrases in the final text — a common local-model failure mode where it loops.
Read itFlagged above 15%. A little repetition is normal in natural prose.
DoRead this as a duplication detector, not a quality score — a low number says the model didn't get stuck, nothing more. If flagged, search the panel for the repeated phrase; it's usually one stuck passage rather than the whole text.

LaBSE alignment

ShowsDocument-wide multilingual semantic alignment for every source/final chunk pair. It flags chunks that fall far below the document's own median similarity.
Read itA flagged chunk is a semantic-drift lead to inspect, not a proven mistranslation. The threshold is document-relative so it does not pretend one absolute score fits every language pair.
SetupNothing to install. Model weights download locally the first time it runs.

Target-language segments

ShowsFinal chunks confidently classified as a language other than the selected target language.
Read itUse it to find untranslated or wrong-language segments. Short passages and low-confidence classifications are intentionally not treated as failures.
SetupNothing to install either — its classifier downloads on first use.

LLM judge — final choose a judge model

ShowsThe same adequacy/fluency rubric as the draft judge, scored on the final text.
Read itIdentical in every respect to the draft judge except which translation it scores — same prompt, same sampled chunks — which is what makes the two numbers subtractable. Flagged if either average is below 3/5.
DoRun this together with the draft judge; the pair is what feeds the adequacy-regression gate in Verdict. Both are averages of five 1–5 ratings, so treat a difference under about 0.5 as noise.

LLM judge — draft vs final choose a judge model

ShowsSide-by-side comparison of the chunks refinement actually changed, order randomised, with the source in front of the judge. Two separate questions: which version conveys the source more faithfully, and which reads better as prose.
Read itReports final / draft / tie for each question separately. Flagged when the draft wins on accuracy. The case worth catching is the split: the final reads better and the draft is more accurate. That is polish bought with meaning, and it is called out in words.
DoThis test used to show two target-language passages with no source and ask which read better — so it graded refinement on exactly the axis refinement optimises, and reported the pass as harmless while accuracy fell. Unchanged chunks are skipped rather than counted as ties, so a low sample count here just means the pass changed little.

COMET-Kiwi — final

ShowsThe same neural quality-estimation score, run on the final text instead of the draft.
Read itHigher is better. Flagged below 60. Sentence-level by design, so it is blind to anything spanning chunks — it cannot see a name drifting.
DoThe shipped text is the final one, so this is the number to quote. Run the draft version too if you want to know whether refinement moved it.
Verdict

Why there is no single score

ShowsDraft → final vectors for adequacy, fluency, COMET-Kiwi and consistency, plus the gates that fired.
Read itThere is no composite score because fluency can improve while adequacy falls. The important failure is a polished final that conveys less than the draft.
DoAn adequacy regression of 0.3 or more, a pairwise judge preferring the draft on accuracy, missing agreed renderings, or unsatisfied exact terms blocks shipment. Source-script leakage warns. Tests that were not run provide no evidence.
