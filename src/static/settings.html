Settings

Choose a model for each role

Tolmach separates glossary preparation, translation, editing, verification, and quality checks into distinct LLM roles. Configure them on the left; the built-in neural components on the right.

Tolmach loads these lists automatically from your local Ollama server.
To add a model, pull it in Ollama and reload this page; Tolmach will add it to the lists. A separate model choice is saved for each role.

A stack that personally produced good results for the author: Glossary preparation gemma4:31b-cloud (32.7B), Translation translategemma:27b (27.4B), Refinement gemma4:31b-cloud (32.7B), Verifier and Judge mistral-large-3:675b-cloud (675B) (cloud open-source models).

Runs during Prepare: reads the source and builds the proposed glossary. Choose a small, fast general instruct model because Prepare makes many short calls. If only one general instruct model is installed, or your computer cannot run several models, you may reuse it for Refinement and Judge; separate models make later checks more independent. A weak choice creates more missing or incorrect suggestions, so you spend more time reviewing before Start.

Runs during the Start stage and produces the first draft — the single biggest factor in the final result. TranslateGemma is built only for translation and has its own native prompt format, which Tolmach uses here; do not select it for any other role. TranslateGemma comes in 4B, 12B, and 27B: for book translation, choose 12B or 27B and avoid the smallest 4B. Other model families — even those specialised for translation — may require code changes to support their prompt templates. If you use a general model instead, choose a different model for Judge.

Runs during the Continue stage after the first draft and rewrites it. Its accepted edits become the final text, so choose a capable general instruct model with strong editing and instruction-following ability. It may share the general instruct model used for Glossary preparation and Judge when hardware or installed-model limits require reuse, but Verifier must still be different. A weak choice either changes too little or replaces good wording with worse text.

Runs during the Verify stage after Refinement and accepts or rejects every proposed edit before it is kept. Choose a model different from Refinement, ideally with more parameters than the Refinement model. A weak or self-reviewing verifier may follow A/B position instead of the source; Tolmach detects that pattern and retries once without ordered versions.

Runs during the Quality Check stage after the final translation is ready. It produces LLM scores and backtranslation diagnostics but does not edit the translation. Choose a capable general instruct model different from the Translation model, and never TranslateGemma because it is translation-only and uses its native translation prompt. It may share the general instruct model used for Glossary preparation or Refinement if necessary, as long as it remains different from Translation. A weak or near-identical Judge can miss errors and make the quality report unreliable.

Built-in components selected by Tolmach, not Ollama roles you choose. GLiNER and BGE-M3 run automatically during Prepare; LaBSE, XLM-R language detection, and COMET-Kiwi run only when you start their individual Quality Check tests. Weights download from Hugging Face on first use, so the first run needs internet access and enough disk space.

GLiNER multilingual NER

Runs automatically during Prepare. It scans the source for candidate people, places, organisations, objects, and titles; Tolmach combines them with its deterministic text scan before building the glossary proposal. Its weights download and cache on first use. Model page on Hugging Face.

Entity recognition
BGE-M3

Runs automatically after entity collection during Prepare. It compares candidate wording and context for evidence that variants name the same person or place; the configured instruct model resolves uncertain identities. Its weights download and cache on first use. Model page on Hugging Face.

Embedding
LaBSE

Runs only when you start the LaBSE alignment Quality Check after Continue. It compares every aligned source/final chunk pair and flags passages where meaning may have drifted. The result is diagnostic: it does not edit the translation or block export. Its weights download and cache on first use. Model page on Hugging Face.

Alignment
XLM-RoBERTa language detection

Runs only when you start the Target-language segments / language-ID Quality Check after Continue. It flags confident wrong-language or untranslated final segments. The result is diagnostic: it does not fix text or block export. Its weights download and cache on first use. Model page on Hugging Face.

Language ID
COMET-Kiwi

Runs only when you start a COMET-Kiwi Quality Check. It estimates translation quality without a reference translation; separate tests score the Start draft and Continue result. Its score is diagnostic and does not edit or block export. The checkpoint is gated and multi-gigabyte: request access on Hugging Face, then run huggingface-cli login or set HF_TOKEN; there is no in-app login. It downloads on first test use. Model page on Hugging Face.

Quality estimate

Used by Verify automatically in the Glossary and Review automatically in Review desk. Glossary verification uses web search and waits for your approval. Review desk sends Source, Draft, Final, and the proposed fixes; the provider chooses apply or keep and Tolmach saves those decisions automatically.

Web search and model tokens may be billed by the provider.

The recommended lightweight model is filled in automatically. You can replace it with any compatible model ID available from this provider.

The key stays only in this browser tab's session storage and is never written to Tolmach databases or logs. Leave it empty when a server environment key is available.
