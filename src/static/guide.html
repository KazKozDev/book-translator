Guide

Translate a book from upload to export

Follow the workflow on the left. Use the reference on the right when a glossary, review, or Quality Check result needs a decision.

Step by step Workflow
  1. Configure models in Settings

    Assign the five local Ollama roles: Glossary preparation, Translation, Refinement, Verifier, and Judge. Use TranslateGemma only for Translation. Verifier should differ from Refinement; Judge should differ from Translation.

  2. Upload the source — → 1 UPLOAD

    Select or drop a .txt, .epub, .pdf, or .docx file. A PDF is read as text — lines are rejoined into paragraphs, and chapter bookmarks or clear chapter headings become chapter breaks when they can be trusted. A scanned PDF with no text layer is refused. A DOCX keeps Heading 1 sections as chapters when present. Choose source language, target language, and genre. The Original text panel shows a preview; Tolmach processes the full uploaded file.

  3. Prepare and review the glossary — optional

    Open Glossary and press → PREPARE. Tolmach scans the whole source, groups recurring names and terms, and proposes target renderings. Existing glossary text is not overwritten.

    Review every line before Start. Delete noise, correct wrong renderings, and add missing terms. The editable draft is saved for this document and language pair, so it does not leak into another book.

  4. Verify glossary renderings — optional

    Configure Glossary API in Settings, then press Verify automatically. The selected provider checks the glossary with web search. Review the proposed changes and choose Apply verified glossary or Keep original. Nothing is applied silently.

  5. Create the draft — → 2 START

    Start translates the book in chunks and streams completed batches into the Translation panel. Glossary terms submitted with Start become the terminology contract for this job.

  6. Refine the draft — → 3 CONTINUE

    Refinement proposes located edits instead of rewriting whole chunks. Verifier compares each patch with the draft against the source; only accepted edits enter the final text. Current job shows found, applied, vetoed, and failed review counts. Log shows the same process per chunk.

  7. Review the final text

    In Review desk, start with Needs review. Compare Source, Draft, and editable Final. Apply fixes manually, or press Review chunk automatically to let the configured cloud provider choose apply or keep and save that chunk. Review all automatically makes one provider pass over every open chunk with applicable fixes. You can also generate two or three alternatives and explicitly choose one.

  8. Run checks, then export

    Quality Check tests run only when you press their arrow. Resolve blocking findings, save any manual edits, then use Copy, TXT, PDF, or EPUB. Recent translations remain in the local Archive and can be opened, continued, retried, downloaded, or deleted.

Glossary

Format and enforcement

Use one entry per line: source => target | mode. Tab-separated source[TAB]target[TAB]mode rows are also accepted. The default mode is inflectable.

exact

Use the target text letter for letter. Best for fixed labels. Terminology delta checks these entries deterministically.

inflectable

Keep the agreed rendering but allow grammatical endings. This is the normal mode for names.

preferred

Use the rendering where it fits; the model may choose another form when context requires it.

Automatic frontier verification sends the glossary and language pair to the selected API provider. It does not send the full book. API usage may be billed. A pasted key stays in the current browser tab session; a server environment key can be used instead.
Review and export

Needs review

Default filter

Shows chunks with warnings, detected issues, terminology signals, or unresolved review state. Use All chunks when you want a complete manual pass.

Proposed fixes

Manual decision

Apply changes one finding. Apply proposed fixes changes every still-applicable finding in the selected chunk. Both edit the Final field only; press Save final to keep the result. Review chunk automatically asks the cloud provider to apply or keep each finding and saves its decision immediately.

Translation options

Model call

Generates two or three alternatives with the Translation model and ranks them with Judge. Tolmach never replaces the final text automatically; choose an option explicitly.

Saved edits

Canonical final

A saved chunk becomes part of the exported final text. Quality results made stale by that edit are cleared and must be rerun. Export is disabled while an edit is unsaved.

Archive

Local SQLite

Open restores panels, review state, and saved checks. Continue resumes refinement on a finished draft. Resume continues an interrupted Stage 1 from the last finished chunk (closing the browser no longer kills a running job). Delete permanently removes the saved job and its chunks.

Translation — after Start

Backtranslation chrF

Diagnostic

Round-trips five draft chunks back to the source language. Below 40 is flagged. This is not a translation-quality score and should not be compared across runs unless the reverse model is fixed.

LLM judge

Judge model

Rates five risk-selected draft chunks for adequacy and fluency. Either average below 3/5 is flagged. Use a Judge different from Translation.

COMET-Kiwi

Gated model

Reference-free neural estimate for the draft. Below 60 is flagged. The gated Hugging Face checkpoint requires access plus huggingface-cli login or HF_TOKEN.

Refinement — whole-document checks

Named-entity consistency

No model

Finds source chunks where an agreed glossary rendering is missing from the final. Inflected forms count. An empty glossary cannot pass this check; it provides no terms to test.

Numbers and dates

No model

Flags digit-written source values missing or changed in the final and lists extra target values. Spelled-out numbers are not covered.

Chunk coverage

No model

Checks that every source chunk has a final chunk in the same position. A count mismatch or blank final chunk is blocking.

Untranslated words

No model

Lists words still written in the source script. Inspect each hit: it may be a deliberate brand or an untranslated name. Shared-alphabet language pairs do not provide a reliable signal.

Terminology delta

No model

Compares exact glossary violations in draft and final. Fewer violations is an improvement. Remaining or newly introduced violations are flagged.

Length ratio

No model

Compares final length with source length. Outside 0.55x–1.6x is flagged as possible truncation or duplication. Interpret within the normal expansion of your language pair.

Diff ratio

No model

Measures draft/final similarity. Below 0.75 is flagged as a likely rewrite. Very high similarity is normal for guarded patching; above 0.995 means almost nothing changed.

Repetition ratio

No model

Measures repeated four-word phrases in the final. Above 15% is flagged. Use it as a duplication detector, not a general quality score.

LaBSE alignment

Local neural model

Checks every aligned source/final chunk and flags semantic outliers relative to this document. A hit is a passage to inspect, not proof of mistranslation.

Target-language segments

Local neural model

Flags final chunks confidently classified as another language. Short or low-confidence passages are not treated as failures.

Refinement — model checks

LLM judge — final

Judge model

Uses the same five chunks and rubric as the draft judge. Adequacy or fluency below 3/5 is flagged. Treat differences under about 0.5 as noise.

LLM judge — draft vs final

Judge model

Compares changed chunks against the source, scoring accuracy separately from readability. Draft wins on accuracy are flagged. The important split is a smoother final that preserves less meaning.

COMET-Kiwi — final

Gated model

Runs the same reference-free estimate on the shipped final. Below 60 is flagged. It works per chunk and cannot detect consistency failures across the book.

Verdict

Read gates, not a composite score

Verdict keeps adequacy, fluency, COMET-Kiwi, terminology, and consistency separate. A single average would hide a final that reads better but preserves less meaning.

Blocking findings

Do not ship

Adequacy regression of 0.3 or more, draft preferred on accuracy, missing agreed name renderings, or unsatisfied exact terms.

Warnings

Inspect

Source-script leakage, semantic outliers, unusual length, high repetition, or an inconclusive model score. Read the affected chunks in Review desk.
