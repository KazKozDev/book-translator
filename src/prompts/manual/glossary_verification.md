## review

Review the following glossary entries and assign only the correct mode to each translation. Do not change the source term or an existing valid translation unless the translation is clearly malformed, contains unrelated added information, or conflicts with the established rendering in the target language. Use `exact` when the translation must appear letter for letter in every context, `inflectable` when the translation should be preserved but may change grammatical form to fit the sentence, and `preferred` when the translation should be used where natural but the app may translate freely when needed. Repair every incomplete or damaged entry instead of omitting it. If a translation is missing, reconstruct the correct translation. If the separator or mode is missing or invalid, restore it and assign the correct mode from `exact`, `inflectable`, or `preferred`; do not assume `inflectable` merely because the mode is absent. Preserve every source term and return the same number of entries you received.

For characters, places, organisations, titles, and other entities from a published work, use the established rendering found in authoritative published translations of that specific work in the target language. Do not invent a new literal translation or transliteration when an established target-language rendering exists. If several published renderings exist, choose the most widely established rendering for that work and use it consistently. Only create a source-grounded translation or transliteration when no established target-language rendering can be verified.

Check the identity of each entity against sources in the original language, and verify its established rendering against authoritative sources and published editions in the target language. Return only the corrected glossary, with one entry per line, using exactly this format: `source term => translation | mode`. Every output entry must include a translation and exactly one mode. Do not add explanations, tables, comments, headings, confidence scores, or sources.

## notes_task

Then, as a second and separate task, find what is known about these entries from the book itself, and add a `{note}` to the entries where it would change the translation.

Establish which book this is first. Use the title and author above when they are given; when they are not, identify the work from the entries themselves, and check whether it belongs to a series. Consult authoritative sources for every character, place, organisation, and term before you conclude anything about it.

Write a note only where your research settles something a translator cannot get from the surrounding sentence: a character's gender, age, or role, a name shared by two people, a term whose established sense in this book differs from its everyday one. A note is one short line of plain text under 200 characters, written in the target language, because the target language is the text it has to shape. Append it after the mode: `source term => translation | mode {note}`.

A note is an instruction the translator will follow, so a wrong note is worse than no note: it will be obeyed. Write one only when you are certain, from a source you could name if asked. Do not guess, and do not infer from a stereotype, from a similar-sounding name, from the genre, or from what would read conveniently. When you are not certain, write no note and leave that entry exactly as it is. Most entries need no note, and a glossary where every line carries one is a glossary of guesses. Where an entry already has a `{note}`, treat it as the author's own knowledge: keep it unless you are certain it is wrong, and never reword one you are merely unsure about.
